## 4. F — 第一性原理

**追问 1：插件化到底在解决什么？**
把系统状态空间分解为可独立演化的小块，并保证"重新组合不产生未定义状态"。因此插件化 = **分解（粒度）+ 身份（可比）+ 生命周期（可逆）+ 传播（最小影响）** 四件事，缺一不可。

**追问 2：为什么必须是"能力"而不是"包"作为依赖单元？**
因为包是**部署单元**（版本、分发、构建），能力是**语义单元**（接口、契约）。若用包做依赖，则"换实现"必然变成"换依赖 + 重建"，空间维可组合性丧失（F1）。故依赖必须指向能力，包只是能力的载体。

**追问 3：为什么撤销必须由登记点负责？**
副作用的发生点是唯一知道"如何逆转"的位置。把撤销责任外移（交给 atexit、交给进程退出、交给人工）必然导致残留无法枚举。故**登记的返回值必须是逆操作**（F4），这是一条不可协商的公理。

**追问 4：为什么变更要按依赖集传播？**
若按"全局重载"传播，代价与系统规模成正比，且破坏无关组件的内部状态；若按"依赖集"传播，代价与受影响子图成正比，且可证明收敛（F11）。故依赖声明不是文档，而是**调度输入**。

**三条公理（XPC 的公理集）**

| 公理 | 表述 | 直接推论 |
|---|---|---|
| A1 身份公理 | 任何被依赖的东西必须有稳定、可复现的身份 | 键规范化 + 摘要身份；禁止 `id()` |
| A2 可逆公理 | 任何状态变更必须伴随可执行的逆操作 | 唯一登记入口返回 Disposable；禁止裸写全局表 |
| A3 局部公理 | 一次变更的影响范围 = 声明依赖的传递闭包 | 依赖必须显式；隐式依赖即缺陷 |

推论：**插件清单不是元数据，而是可执行契约**；**装配器不是启动脚本，而是求解器**；**快照不是输入，而是解的输出**。
