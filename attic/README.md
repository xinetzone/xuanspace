# attic/ - 归档目录

## 概述

`attic/` 目录存放 Xuanspace（玄境）项目中已废弃但因历史原因需要保留参考的代码。这是一个代码"阁楼"——存放不再维护、不再参与构建，但偶尔需要查阅的旧代码。

**重要提示**：放入 attic 的代码是"死代码"，不要在生产环境或新开发中依赖这里的任何内容。

## 用途

本目录存放以下类型的代码：

- 已被新实现完全替代，但重写过程中可能需要参考逻辑的旧模块
- 因产品需求变更而废弃，但可能重新启用的功能原型
- 实验性/探索性代码，未进入正式发布但有参考价值
- 历史版本的兼容性代码，已不再需要支持
- 被弃用的脚本、工具，完全不再使用但删除前需要缓冲期
- 临时保留的迁移前代码备份

## 分类标准

代码应放入 `attic/` 当且仅当满足以下条件：

1. **不再维护**：当前开发者没有计划继续维护或更新这段代码
2. **不再参与构建**：代码不被任何活跃代码导入，不参与项目构建流程
3. **有保留价值**：存在合理的查阅需求（不是纯粹的垃圾代码）
4. **有替代方案**：已有新的实现、新的方式，或明确决定不再需要该功能

**判断原则**：如果你犹豫是否应该删除某段代码，先放入 attic 观察 3 个月。3 个月内无人查阅即可考虑永久删除。

## 什么不应放入 attic

- **仍在使用的代码** → 应放在对应功能目录（libs/apps/tools）
- **临时调试脚本** → 用完即删，不要入库
- **敏感信息（密钥、密码）** → 绝对不能放入 Git，包括 attic
- **可从 Git 历史恢复的代码** → 直接删除即可，Git 历史就是最好的归档
- **vendor 代码** → vendor 目录有自己的管理策略，不属于 attic

## 归档规则与流程

### 归档前必须完成的事项

将代码移入 `attic/` 前，**必须**：

1. **添加 ATTRIBUTIONS.md 文件**：在被归档的子目录中创建归档说明文件（见下文模板）
2. **移除引用**：搜索整个代码库，确保没有活跃代码仍然导入或引用该模块
3. **更新文档**：在 CHANGELOG 或相关文档中注明该模块已废弃
4. **通知团队**：通过团队沟通渠道告知相关开发者模块已归档
5. **确保 CI 通过**：归档后 CI 流水线应正常通过（attic 代码不参与构建）

### ATTRIBUTIONS.md 模板

每个归档子目录**必须**包含 `ATTRIBUTIONS.md` 文件，格式如下：

```markdown
# 归档说明：<模块名称>

## 基本信息
- **原位置**：libs/xuan-old-module/（原目录路径）
- **归档日期**：2024-01-15
- **归档操作人**：张三
- **废弃版本**：v0.3.0（从哪个版本开始废弃）
- **计划删除时间**：2024-04-15（归档后 3 个月，如无查阅则删除）

## 废弃原因
（简要说明为什么这段代码被废弃：有了更好的实现？技术栈更换？需求移除？）

## 替代方案
（说明应该用什么替代这段代码。如果没有替代方案，说明为什么不再需要该功能。）

- 新位置：libs/xuan-new-module/
- 迁移指南：参见 docs/developer-guide/migration/old-to-new.md
- 替代 API：new_function() 替代 old_function()

## 历史价值
（说明为什么需要保留这段代码作为参考——比如包含什么特殊算法、什么业务逻辑值得参考）

## 归档时的状态
- [ ] 已确认无活跃代码导入此模块
- [ ] 已从 pyproject.toml dependencies 中移除
- [ ] 已更新相关文档
- [ ] 已通知团队成员
```

### 归档操作步骤

```bash
# 1. 创建归档目标目录
mkdir -p attic/old-module-name

# 2. 移动代码（保留 Git 历史的方式，使用 git mv）
git mv libs/old-module/* attic/old-module-name/

# 3. 添加 ATTRIBUTIONS.md
# （编写归档说明文件）

# 4. 从根 pyproject.toml 的 workspace packages 中移除（如果之前在列表中）
# （编辑 pyproject.toml）

# 5. 搜索并移除所有引用
# grep -r "old_module" --include="*.py" libs/ apps/ tools/

# 6. 运行测试和 CI 确保没问题
pdm run pytest

# 7. 提交
git commit -m "chore: archive old-module-name (replaced by new-module)"
```

## 命名规范

- 子目录名**保留原有名称**，不做重命名，便于追溯
- 如果归档多个相关模块，可以创建子子目录按主题分组
- 名称中可包含归档日期后缀（可选），如 `old-module-20240115`

**示例**：
- `xuan-old-parser/` - 保留原模块名
- `legacy-cli-v1/` - 第一版 CLI 遗留代码
- `experiments/2023-q4-new-algorithm/` - 按实验分组

## 重要保证与免责声明

**attic/ 中的代码：**

1. **不参与构建**：根 `pyproject.toml` 的 workspace packages 不包含 attic 目录
2. **不被导入**：活跃代码不应从 attic 导入任何模块
3. **不保证可运行**：代码可能依赖已删除的其他模块，可能无法运行或测试通过
4. **不保证安全性**：归档代码可能包含已知漏洞，不会被修复
5. **无依赖保证**：依赖的第三方包版本可能不再兼容，不会更新
6. **随时可能删除**：超过保留期限（通常 3-6 个月）且无人查阅的代码会被永久删除
7. **不接受 PR**：attic 中的代码不再接受功能更新或 Bug 修复 PR

**从 attic 恢复代码的正确流程**：

如果需要重新启用归档的代码，**不要**直接在 attic 中修改：

1. 将代码从 attic 移出到正确目录（libs/apps/tools）
2. 更新 ATTRIBUTIONS.md 说明恢复原因
3. 更新代码以适配当前项目结构和依赖
4. 添加测试，确保功能正常
5. 在文档中说明该模块重新启用

## 定期清理

建议每半年对 attic/ 进行一次清理：

1. 检查每个归档模块的 `计划删除时间`
2. 查看 Git 日志，确认归档后是否有人查阅过该目录
3. 对于超期且无人查阅的代码，发送删除通知给团队
4. 一周后无异议则永久删除（从 Git 中完全移除）
5. 更新本 README 的归档列表
